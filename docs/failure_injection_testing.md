**Project:** Lineage-Aware Autonomous Data Pipeline Incident Detection & Recovery Platform

## 1. Purpose

Failure injection testing validates that the incident platform can safely detect, investigate, recover from, and verify controlled data-pipeline failures.

The tests are intentionally designed to prove the full incident lifecycle:

```text
Controlled Failure
↓
Detection
↓
Incident Creation
↓
RCA
↓
Deterministic Recovery Decision
↓
Safe Execution
↓
Validation
↓
Incident Resolution
```

The goal is not only to prove that recovery works, but also that unsafe or stale recovery workers are prevented from making changes.

---

## 2. Test Principles

Every failure-injection scenario follows these principles:

- failures are deliberate and reversible
- the target dataset is known
- expected failure signatures are defined before injection
- runtime provenance is captured
- recovery is allowlisted
- validation is mandatory
- recovery is not considered successful until the dataset is healthy again
- audit evidence is persisted

## 13. Causality Guardrail

A valid recovery decision requires deterministic evidence that supports causality.

Example:

```text
Injected Column
=
Observed Unexpected Column
=
Runtime Provenance Column
```

If the evidence does not align, automatic recovery should not proceed.

This prevents the LLM from inventing or overgeneralizing a root cause.
